## Summary and checked invariants

This review establishes the first codebase-review baseline whose reviewed commit is reachable from `main`. It covers all maintained Python under `src/`, `deployment/cloudflare/` and `scripts/`, the browser JavaScript and CSS, theme data (SVGs spot-checked for script and foreign content), all tests, hooks, workflows and project configuration. The local environment was macOS (Darwin 25.6, arm64), Python 3.12.12, uv 0.12.17, Node 26.10.0 and Biome 2.5.14. The delta from the last landed review record (`5832d4c`, PR #8) to the reviewed commit is 168 files, +13,520/-336 lines, almost all hosting, Cloudflare and recovery work. `src/sway/engine/` has no changes in that range.

Each area reviewer reported failure scenarios and the invariants that held. The coordinator re-read the cited source for every finding below and reran every `Verified` reproduction against this checkout. Scratch reproductions lived under `/tmp` and are described inline; no tracked file was modified for them.

No P0 or P1 finding was found. These invariants held:

- **Rules.** The 26 Kingdom definitions match the second-edition reference, including reaction timing, Throne Room with attacks, Merchant, Library, Sentry and the fewest-turns tiebreak. A random-play fuzz of about 18,000 decisions across 2-4 players and random Kingdoms found no conservation, duplicate-ID, negative-resource or stray temporary-zone failure. Every reachable state validated and restored, and resumed and uninterrupted runs produced identical transitions. 80 mixed-profile bot games all finished without an illegal choice.
- **Stale and duplicate commands.** The engine checks revision, decision ID, duplicates, counts and option membership before copying state. Local storage re-checks the revision under `BEGIN IMMEDIATE` and enforces a unique command ID. Hosted receipts are looked up before lifecycle checks; reuse with a different payload is a conflict; the receipt and snapshot commit in one write, and the write re-runs membership checks after computing outside the transaction.
- **Privacy.** Templates and bots receive only `view_for` output. Opponent hands, deck order and inspected cards never appeared in another player's view during the fuzz run. Hosted routes resolve the seat from the session, never from form fields, and return 404 to non-members. Logs record exception types only. Invitation secrets stay in URL fragments and are removed from history.
- **Authentication and request boundary.** Hosted cookies use `__Host-`, Secure, HttpOnly and SameSite=Lax. CSRF tokens are compared in constant time; mutations require an exact Origin, form encoding and a bounded body. Invitation claims are conditional updates inside one write, so a race has one winner. Local mutations check the CSRF cookie, Origin and `Sec-Fetch-Site`, and the server binds to localhost.
- **Cloudflare atomicity and recovery.** `Runtime.execute` commits each operation and its alarm in one Durable Object transaction; the real-workerd contract proves joint rollback. The recovery RPC has no HTTP route, requires maintenance mode and an exact object ID, and the drill config disables `workers_dev` and preview URLs. The operator client writes its receipt with fsync before requesting a restore and resumes safely after a lost response.
- **Self-host backup.** It uses the SQLite online backup API, exclusive mode-0600 files, integrity and foreign-key checks, and removes partial copies on failure.
- **Gates.** `_common.sh` sets `pipefail`; `e2e.sh` preserves pytest's status through `tee`; empty collection fails once code exists; the Biome binary is checksum-verified; the wheel smoke test runs isolated from the checkout; both workflows use `contents: read` and no `pull_request_target`.

## Findings

### Bug

- `pending-bot-scan-undecodable-room` — **One undecodable active room stops all hosted bot progress, and on Cloudflare every request fails.** Bug · Open · Verified.
  - Where: `src/sway/hosting/service.py:684` (`pending_bot_games`, which deserializes every candidate through `_bot_pending`/`_record`), `deployment/cloudflare/src/entry.py:86` (`Runtime.execute`) and `:153-155` (`Installation.alarm`), `src/sway/hosting/dispatcher.py:67-73` (`_scan`).
  - Severity: P2 Normal.
  - If one active `bot_pending=1` room holds a snapshot the running code cannot load (for example after a deploy that changes the save or bot version), the scan raises `SaveFormatError`. Self-hosted, the dispatcher logs a warning every 5 s and schedules no bot work for any table. On Cloudflare the scan runs inside every operation's transaction, so authentication, anonymous sessions, table listing, creation and the host's own cancel all roll back. Reproduced with the real services: the self-host scan raises and a healthy game is not scheduled; under the Cloudflare `Runtime` with a SQLite-backed fake of the Durable Object storage API, authenticate, list, create and new anonymous sessions all fail while the same call without the wrapper succeeds. Isolate decode failures per room (pause and report that room) and arm the alarm from a cheap SQL existence check rather than full deserialization.
  - Review backlog: `hosted-bot-scan-resilience`

- `join-seated-conflict-500` — **A seated player who opens another invitation to the same table gets an internal server error.** Bug · Open · Verified.
  - Where: `src/sway/hosting/web.py:426-428` (`join`), `src/sway/hosting/service.py:354-355` (`join`).
  - Severity: P2 Normal.
  - `service.join` raises `StorageConflict("You already occupy a seat…")`, which has no exception handler and is not caught in the route. Reproduced with TestClient: the host opens their own invitation and submits it, and the response is 500. Map the conflict to the invitation page with a clear message.
  - Review backlog: `request-error-responses`

- `recovery-error-ends-session` — **A mistyped recovery code reports an ended session and deletes the cookie.** Bug · Open · Verified.
  - Where: `src/sway/hosting/web.py:145-161` (`expired`), `src/sway/hosting/identity.py:119-126` (`recover`).
  - Severity: P2 Normal.
  - `recover` raises `AuthenticationError` for an invalid code, and the global handler answers 401 "Your session has ended" and clears the cookie. Reproduced: `POST /recover` with `typo` returns 401 with `set-cookie: __Host-sway_session=""`. The same handler fires when a 30-minute anonymous session expires before `POST /join`; `hosted.js` has already removed the secret from the URL, so the invitee cannot retry from that page. Distinguish invalid credentials from expired sessions and keep the invitation flow recoverable.
  - Review backlog: `request-error-responses`

- `hosted-seat-integer-overflow-500` — **An oversized seat number returns an internal server error.** Bug · Open · Verified.
  - Where: `src/sway/hosting/web.py:343`, `:352`, `:357` (`table_action`), bound in `src/sway/hosting/service.py:294` and `:322`.
  - Severity: P3 Low.
  - `int()` accepts a 30-digit value and the SQLite bind raises `OverflowError`. Reproduced: `invite` and `revoke-invite` with `seat=9…9` (30 digits) return 500. Only members past the CSRF check can trigger it. Bound integer form fields before use.
  - Review backlog: `request-error-responses`

- `local-malformed-csrf-500` — **A malformed CSRF field on the local app returns 500 instead of 403.** Bug · Open · Verified.
  - Where: `src/sway/web.py:82-85` (`_check_mutation`).
  - Severity: P3 Low.
  - A file upload in `csrf` raises `ValueError` from `_field`, and a non-ASCII token makes `secrets.compare_digest` raise `TypeError`; neither reaches the `PermissionError` handler. Reproduced: both cases return 500. Treat any malformed token as an expired form.
  - Review backlog: `request-error-responses`

### Performance

- `anonymous-sessions-never-purged` — **Every cookieless page load stores a session row that is never deleted.** Performance · Open · Verified.
  - Where: `src/sway/hosting/web.py:104-109` (`anonymous`), `src/sway/hosting/identity.py:165-178` (`_issue`).
  - Severity: P2 Normal.
  - Expiry is only checked on read, and the only session deletions are in principal creation, recovery and revocation. Reproduced: 50 cookieless `GET /` requests leave 51 anonymous rows. At the hard-coded 300 reads per minute per peer, one client can add roughly 430,000 rows a day to the installation's single database or Durable Object. Purge expired sessions in bounded batches.
  - Review backlog: `anonymous-session-retention`

### Design

- `shared-proxy-read-budget` — **Behind the documented same-machine proxy, all self-hosted players share one fixed read budget.** Design · Open · Read.
  - Where: `src/sway/hosting/http.py:35-50` (`HostedBoundary.__call__`); `docs/HOSTING.md:105-110`.
  - Severity: P2 Normal.
  - Forwarded headers are deliberately ignored, so every proxied request has the proxy's peer address. Each visible table tab polls every 2 s (`src/sway/static/hosted.js:33`), so about ten visible tabs across the installation reach the non-configurable 300-per-minute read limit and every player receives 429s. `GET /join/…` counts against the shared 10-per-minute credential budget, so any unauthenticated client can block joins and recovery. HOSTING.md acknowledges the shared identity but gives operators no way to size the read limit. Cloudflare is unaffected because it keys on `CF-Connecting-IP`.
  - Review backlog: none (inventory).

- `lobby-refresh-discards-setup-edits` — **Any lobby change discards the host's unsaved setup edits and drops focus.** Design · Open · Read.
  - Where: `src/sway/static/hosted.js:69-83` (`apply`), `src/sway/hosting/presentation.py:298-303`, `src/sway/static/app.js:84-87` (`afterSwap`).
  - Severity: P3 Low.
  - Joins, readiness changes, setup changes and seat removals bump `lobby_revision` (`_bump`, `service.py:158`), and the next poll replaces `#table`. The open "Change table setup" panel collapses with its edits, and because the lobby has none of the fallback headings, focus falls back to the document body. No browser test covers a lobby refresh during editing.
  - Review backlog: `refresh-preserves-local-ui-state`

- `local-refresh-collapses-panels-and-focus` — **Board refreshes during bot turns close open panels and move focus from controls without an ID.** Design · Open · Read.
  - Where: `src/sway/static/app.js:84-87` (`afterSwap`), `src/sway/presentation/components.py:610` and `:730` (`details`), `:677` (`load delay:250ms`).
  - Severity: P3 Low.
  - Each automatic bot step replaces `#board`. An open public-cards or trash panel collapses, and focus on a `summary`, link or unnamed button jumps to `#opponent-heading`, so a keyboard or screen-reader user cannot inspect an opponent's cards during that opponent's turn. The only focus-preservation browser test uses `#theme-select`, which has an ID.
  - Review backlog: `refresh-preserves-local-ui-state`

- `reaction-prompt-reveals-moat` — **Being offered the Moat reaction tells opponents the defender holds one, even if declined.** Design · Open · Verified.
  - Where: `src/sway/engine/core.py:514-516` (`_execute`, reaction prompt only when k16 is in hand), `src/sway/engine/core.py:260` (`view_for`, public `decision_owner`).
  - Severity: P3 Low.

- `local-trusted-host-testserver` — **The local application's host allowlist includes the test-only name `testserver`.** Design · Open · Verified.

- `display-name-unicode-controls` — **Hosted display names accept bidirectional overrides and other non-printing characters.** Design · Open · Read.
  - Where: `src/sway/hosting/identity.py:95` (`create_principal`); form limit `src/sway/hosting/presentation.py:58` and `:326`.

## Suggested work order and verification limits

1. `hosted-bot-scan-resilience`: the only finding that can take a deployed installation offline. Do it before any change to save or bot versions.
2. `privacy-and-csrf-regression-tests`: protects the privacy and request-boundary invariants that later work relies on.
3. `request-error-responses` and `anonymous-session-retention`: user-visible hosted errors and unbounded storage growth.
4. `daily-and-ci-evidence-fidelity` and `quality-gate-configuration`: CI changes need the explicit authorization noted in `workflow-gate-automation`. Coordinate with that entry.
5. `refresh-preserves-local-ui-state`.

Limits:

- macOS arm64 only. CI's Linux run was not reproduced locally.
- Chromium only. The browser suite needed no sandbox exception in this environment.
- Cloudflare evidence comes from local workerd and a SQLite-backed fake of the Durable Object storage API. No remote deployment, PITR restore or production capacity measurement was performed.
